# Ночной прогон: Claude Code сам выполняет очередь задач

Этой папкой новый сайт AIQME (`aiqme-site/`) собран почти целиком без присмотра: 31 задача из 33
за 19–24.10.2026, по ночам, в том числе на ноутбуке с закрытой крышкой. Код написан под этот
проект, но устроен просто, и его легко переложить на другой.

## Как устроен цикл

```
tasks.json ──► night.py ──► на каждую задачу по порядку:
                 1. автор: claude --print, bypassPermissions + deny-лист
                 2. оркестратор: изменены только разрешённые пути? HEAD и ветка не тронуты?
                 3. проверки: aiqme-site/bin/check (+ bin/browser-check)
                 4. приёмщик: отдельная сессия --restricted, только чтение, вердикт по критериям «done»
                 5. замечания или красные проверки → один круг доработки автором
                 6. принято → коммит «night: W-xx»; нет → git stash «night-blocked W-xx»,
                    зависящие задачи пропускаются
```

- Коммиты, ветки и stash делает только оркестратор. Автору `git commit/push/switch/stash` запрещены
  deny-листом (он действует и в `bypassPermissions`).
- `night-run.sh` создаёт ветку `auto/night-<время>` и на время прогона подменяет
  `remote.origin.pushurl`, так что push невозможен. Утром ветку смотрит человек и сам вливает в `main`.
- Задача считается выполненной, если в истории есть коммит `night: W-xx`. Поэтому `--resume`
  просто продолжает с первой невыполненной.
- Потолок расхода — доля недельного лимита (по умолчанию 15 %). Токены берутся из `modelUsage`
  ответа `claude --print --output-format json`. Если сессия расход не сообщила, прогон останавливается.
- Вердикты приёмщика копятся в `review-stats.jsonl`: по ним видно, где приёмка ловит ошибки, а где
  только тратит токены.

## Файлы

| Файл | Что это |
|---|---|
| `night.py` | оркестратор: промпты автора и приёмщика, deny-листы, проверки, бюджет, журнал |
| `night-run.sh` | запуск: проверка чистого дерева, ветка, отключение push, параметры через `AIQME_*` |
| `night-netwatch.sh` | сторож сети: 4 неудачных `curl api.anthropic.com` подряд (~2 мин) → стоп, работа в stash |
| `night-supervise.sh <срок>` | ждёт возвращения сети и продолжает прогон до срока |
| `night-at.sh ЧЧ:ММ [часов]` | будильник: ноутбук засыпает, просыпается по `rtcwake` и сам запускает прогон |
| `morning-run.sh` | часть `night-at.sh`, работает в службе systemd после пробуждения |
| `finish-all.sh <срок>` | дождаться текущего прогона и догнать остальные задачи |
| `timer-runs.md` | что выяснилось на практике: крышка, сеть после пробуждения, sudo |
| `preflight.sh`, `prepare-aiqme-run.sh`, `return-results.sh`, `codex-command.md`, `claude-settings.local.json` | ранний вариант с отдельной учётной записью Linux для агента; в итоге не использовался |

Очередь задач — [`../tasks.json`](../tasks.json): общие `rules` и задачи с полями `id`, `depends`,
`inputs`, `result`, `touches`, `done` (критерии приёмки) и `checks`.

## Ноутбук с закрытой крышкой

- По умолчанию logind усыпляет ноутбук при закрытой крышке, даже сразу после пробуждения по `rtcwake`.
  Помогает обернуть весь прогон в `systemd-inhibit --what=sleep:handle-lid-switch`. Когда прогон
  кончается и блокировка снимается, ноутбук с закрытой крышкой засыпает сам. Править `logind.conf` не нужно.
- Прогон запускать только после удачного `curl https://api.anthropic.com`. Фиксированной паузы после
  пробуждения мало: Claude получает `EAI_AGAIN`.
- `sudo` (для `rtcwake`) запрашивается вечером, и `rtcwake` идёт последней командой перед сном.
  Утром пароль уже недействителен.
- Чтобы прогон пережил закрытие терминала, он идёт в службе: `systemd-run --user --unit=aiqme-night …`.
  Ход прогона: `journalctl --user -fu aiqme-night`.

## Как переложить на свой проект

1. В `night.py` поменять константы `TASKS`, `ALLOWED`, `PROGRESS`, `FORBIDDEN`, списки `DENY`
   и `REVIEW_DENY`, путь к проверкам (`aiqme-site/bin/check`) и тексты `WORK_PROMPT` и `REVIEW_PROMPT`.
2. Написать свой `tasks.json` с проверяемыми критериями `done`: по ним работает приёмщик.
3. Сделать одну быструю команду проверок (линтер, тесты), которая завершается с ненулевым кодом при ошибке.
4. Посмотреть план без запуска: `python3 night.py --dry-run`. Потом пробный запуск одной задачи:
   `bash night-run.sh --only W-01`.
5. Для запуска по будильнику сначала короткая проба: `night-at.sh` на 3 минуты вперёд с закрытой крышкой.

Нужны: Linux с systemd, Claude Code с выполненным входом, `git`, `python3`, `curl`, `nmcli`
(только для включения Wi-Fi). Журналы и сводки пишутся в `~/.local/share/aiqme/night-<время>/`
(`AIQME_NIGHTS`).
