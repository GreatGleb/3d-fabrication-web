# Оставшиеся решения

[← План](README.md). Список для разработчика (Глеба). Заказчику сейчас вопросов не задаём; возражения после передачи исправляются обновлениями. Для каждого пункта указан **вариант по умолчанию**: с ним задачи выполняются без ожидания. Вариант по умолчанию — рекомендация, а не согласие заказчика или бухгалтера. Пункты с пометкой «данные» нельзя закрыть выбором: нужны реальные сведения, вымышленные рабочие значения запрещены.

### D-01

**Хостинг.** Сервер не арендован, на нём будут другие сайты, включая более крупный проект. По умолчанию: VPS в ЕС, Ubuntu LTS, отдельный Docker Compose на каждый проект, общий обратный прокси с TLS, лимиты ресурсов на контейнеры ([§8.1](08-operations.md#81-размещение-d-01-рекомендация)). Размер — сумма требований проектов; для AIQME строка требований появится в W-20. Нагрузку другого проекта не придумываем.

### D-02

**БД.** PostgreSQL 17 проверен экспериментом (это доказательство работоспособности эксперимента, а не утверждение). По умолчанию — PostgreSQL 17, отдельная БД и роль. Альтернатива — общий кластер крупного проекта с отдельной БД и ролью.

### D-03

**Фоновое выполнение.** По умолчанию: драйвер очереди `database`, один процесс `queue:work`, `schedule:run` раз в минуту. Redis — только если он уже нужен на сервере другим проектам и выделен отдельной БД/префиксом.

### D-04

**Момент выпуска счёта и виды документов** не определены. По умолчанию (настраиваемо): итоговый счёт-фактура на подтверждённую сумму при полной оплате; для авансов — подтверждение платежа в кабинете без номера счёта. Альтернативы: счёт на каждый платёж; проформа при запросе оплаты. До рабочего выпуска нужен ответ бухгалтера — сейчас не запрашиваем.

### D-05

**Данные: реквизиты продавца, статус плательщика VAT и ставка, серия и начальный номер счетов.** Без них выпуск счёта блокируется, в админке предупреждение. Демо-НДС 21 % не используется; Stripe Tax и Stripe Invoicing не выбраны.

### D-06

**Сроки оплаты и срок действия цены.** По умолчанию автоматических сроков нет: платёжный запрос открыт, пока администратор его не отменит; цена действует, пока заказ не изменён. Напоминаний и автозакрытия нет (В-033).

### D-07

**Возвраты.** Правила не определены. По умолчанию: возврат выполняется вручную в Stripe Dashboard. AIQME записывает его по webhook `charge.refunded` как транзакцию возврата и показывает. Кнопки возврата в AIQME нет; отмена заказа деньги не возвращает. Уменьшение цены ниже оплаченного блокируется.

### D-08

**Подготовительная плата для нескольких STL.** По умолчанию: `оценка = Σ масс × цена за грамм + плата за заказ + число файлов × плата за файл`. Плата за файл по умолчанию 0, поэтому прежние 5 EUR берутся один раз на заказ. Оба значения — настройки админки.

### D-09

**Данные: реальные тарифы, материалы и плотности.** До их получения используются существующие примерные значения ядра (PLA 1,24, ABS 1,04, PETG 1,27 г/см³; 0,10 за грамм; плата 5) в EUR, с пометкой «не подтверждено» в админке. На сайте результат подписан как предварительная оценка; окончательную цену подтверждает администратор.

### D-10

**Гостевой доступ и связь с клиентом.** По умолчанию: после отправки гость получает секретную ссылку на заказ; администратор может скопировать её и перевыпустить. Автоматических писем клиенту (подтверждение, запрос оплаты) нет — так ограничен объём уведомлений (В-052). Администратор сообщает о запросе оплаты своим каналом. Привязка гостевого заказа к аккаунту не делается. Если на передаче заказчик захочет письмо клиенту о запросе оплаты — это небольшое добавление в W-16.

### D-11

**Исходный контент.** Тексты услуг, главной, «О нас», FAQ и 3 статей импортируются из прототипа. Три проекта прототипа иллюстративны, тексты политик помечены там как демонстрационные. По умолчанию они импортируются **черновиками**, а разделы показывают согласованную заглушку до публикации реального материала — это расширение правила заглушек, его можно отменить публикацией. Cookie: используются только необходимые, поэтому вместо выбора аналитики — информационная плашка.

### D-12

**Продажа товаров каталога.** Правила продажи и склада не утверждены, демо-ассортимент не продаётся. По умолчанию: опубликованная карточка показывает товар и «Запросить предложение»; корзина товаров — пустое состояние со ссылкой на калькулятор. Включение продаж — отдельная задача (связь карточки с вариантом Lunar, цена, налоги, доставка).

### D-13

**Хранение.** Модели зарегистрированных клиентов — до удаления (решено). Сроки документов и копий не определены. По умолчанию: копия ежедневно, 14 дневных + 8 недельных на сервере и копия вне сервера в хранилище владельца; документы и заказы автоматически не удаляются. Место внешней копии — данные владельца.

### D-14

**Исходники.** Аккаунты и хранилище будут принадлежать заказчику; контакт для доступов не указан. Решение пользователя 18.10: весь корень рабочего пространства публикуется в **публичный** репозиторий `GreatGleb/3d-fabrication-web` — тот же, где был прежний лендинг; Pages раздаёт сборки из папок. Поэтому приватное (переписка и материалы заказчика, аудит и исходники прототипа, исторический цикл плана, `instance/`, `.env`, снимки-архивы) исключено корневым `.gitignore`, а секреты и реальные данные в код не попадают никогда. Передача заказчику — копией или зеркалом репозитория на его аккаунт. `git init`, commit и push выполняет пользователь.

### D-15

**Почта.** Неизвестно, как обслуживается почта aiqme.com. По умолчанию: SMTP почтового ящика домена или транзакционный сервис на аккаунте владельца; From — адрес домена, Reply-To — клиент. Перед рабочим подключением проверить MX/SPF/DKIM/DMARC и не менять почтовые DNS-записи.

### D-16

**Демо-сборка.** Добавлено 18.10 вместе с R-041. Репозиторий корня публичный, Pages раздаёт его с корня ветки `main` (корневой `.nojekyll`). По умолчанию готовая демо-сборка хранится в отслеживаемой папке `aiqme-site/demo/` и открывается по адресу https://greatgleb.github.io/3d-fabrication-web/aiqme-site/demo/ — так же, как прежний лендинг из `legacy-landing/github-pages/`. Отдельный репозиторий не нужен. В папку попадает только статическая сборка без секретов и данных заказчика. Сборка W-24 от решения не зависит; публикация (commit и push папки) — по разрешению пользователя.
