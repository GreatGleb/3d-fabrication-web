# 8. Эксплуатация

[← План](README.md). Сервер ещё не арендован. На нём будут несколько сайтов, включая другой более крупный проект. Хостинг, окончательная БД и способ фонового выполнения не утверждены. Ниже — рекомендации, явно помеченные; нагрузку другого проекта не придумываем.

## 8.1. Размещение (D-01, рекомендация)

- VPS в ЕС (рынок — Литва), Ubuntu LTS.
- Каждый проект — отдельный **Docker Compose** проект: собственные контейнеры, сеть, тома, `.env`, пользователь и БД. AIQME: `app` (PHP-FPM 8.4), `web` (nginx), `worker` (`queue:work`), `scheduler` (`schedule:run`), `db` (PostgreSQL 17), собственный том `storage`.
- Один общий обратный прокси на хосте (Caddy с автоматическим TLS или уже выбранный для крупного проекта) маршрутизирует домены по сетям проектов. У прокси нет доступа к данным проектов.
- Лимиты CPU и памяти на контейнеры AIQME, чтобы один проект не вытеснял другие.
- Почему не «голый» хост с общими PHP-FPM и PostgreSQL: Compose даёт одинаковую среду локально и на сервере, изоляцию процессов и секретов без настройки пользователей ОС для каждого сайта. Если крупный проект уже использует общий PostgreSQL, допустим общий кластер с отдельной БД и ролью AIQME (D-02).

## 8.2. Размер сервера

Считается по сумме нагрузок, а не только AIQME. Для AIQME задача W-20 **измеряет** локально: память PHP-FPM под нагрузкой страниц, пик памяти серверного анализа STL на 25 МиБ / 500 000 треугольников, генерацию PDF, PostgreSQL в простое, рост диска (STL заказов: ориентир по старому плану — около 1,5 ГиБ за 30 дней при 10 файлах по 5 МиБ в сутки; это арифметика гипотезы, не измерение). Итог — строка «AIQME требует ≈ X ГБ RAM, Y vCPU, Z ГБ диска + рост», которую складывают с требованиями других проектов. Бюджет 10 USD/мес — старый предварительный ориентир для одного AIQME, не бюджет общего сервера.

## 8.3. Развёртывание

- Исходники — каталог `aiqme-site/` в публичном Git-репозитории корня `GreatGleb/3d-fabrication-web` (D-14; приватное исключено `.gitignore`, секреты — только в `.env` на сервере). Деплой: `git archive` нужной версии каталога `aiqme-site/` без `experiments/` на сервер → `docker compose build` → `php artisan migrate --force` → `optimize` → перезапуск `worker`. На сервер не попадают `legacy-landing/` (включая `instance/`), `docs/` (переписка и материалы заказчика), `aiqme-site/experiments/` и тестовые фикстуры.
- Миграции — только совместимые вперёд. Откат кода не откатывает схему; после реальных заказов старую БД поверх новых данных не восстанавливаем.
- `.env` создаётся на сервере по шаблону `.env.example` без значений; в Git его нет.
- Перед первым запуском на aiqme.com: выписать текущие DNS-записи (A/AAAA/CNAME, MX, SPF/DKIM/DMARC, верификации, CAA), менять только веб-записи, не трогать почту info@aiqme.com. Сначала проверка на временном поддомене или IP, затем переключение.
- Stripe webhook endpoint регистрируется на рабочем домене до приёма первых оплат.
- Существующая статическая V2 на GitHub Pages (`legacy-landing/github-pages/`, https://greatgleb.github.io/3d-fabrication-web/legacy-landing/github-pages/) остаётся демонстрацией прежнего лендинга; рабочую коммерческую платформу там не размещаем (ограничение GitHub Pages). Демо нового сайта — отдельно, §8.7.

## 8.4. Фоновые задания

D-03, рекомендация: очередь `database`, один `worker` (очереди `default`, `sheets`, `mail`), `scheduler` раз в минуту. Задания планировщика: повтор недоставленных `integration_events` (каждые 5 минут), проверка файлов-сирот (ночью), резервная копия (ночью), очистка устаревших сессий и токенов сброса. Наблюдение — Overview админки (неудачные задания, события «на сверку», давность последней копии) и бесплатная внешняя проверка доступности `/up` (например UptimeRobot на аккаунте владельца — уровень P).

## 8.5. Резервные копии и восстановление

- **Рекомендация** (D-13): ежедневно `pg_dump` + архив `storage/app/private` и медиа. Хранить 14 дневных и 8 недельных копий на сервере и копию **вне сервера** в хранилище владельца. Место внешней копии, сроки хранения документов и копий не определены.
- Копия — единый комплект: дамп и файлы одного запуска, с манифестом sha256. Проверка комплекта: у каждой ссылки на файл в дампе есть байты с тем же хешем.
- Восстановление (чек-лист): остановить `worker` и `scheduler` → восстановить БД и файлы → сверить хеши → сверить платежи Stripe после времени копии (успешные списания, которых нет в БД, вносятся по событиям Stripe, а не заново) → проверить, что номер следующего счёта больше последнего выданного (учёт выпущенных PDF и Sheets) → сбросить сессии → запустить.
- Одна реальная проверка восстановления — локально, на копии с синтетическими данными (W-20). Тестовое восстановление не получает рабочих ключей Stripe, почты, бота и Sheets.
- Цель простоя — желательно не больше часа, допустимы сутки (В-061); это цель, а не гарантия.

## 8.6. Поддержка

После запуска сбой сначала пытается устранить заказчик, затем звонит разработчику (В-064). Задача W-21 готовит короткую инструкцию: где смотреть ошибки, как перезапустить worker, как восстановить копию, как сменить ключи.

## 8.7. Демо-сборка для GitHub Pages (рекомендация)

Требование — [§1.6](01-scope.md#16-демо-сборка-для-github-pages), задача [W-24](tasks.md#w-24). Ниже — рекомендуемый механизм, не утверждённое решение.

- **Источник — то же приложение.** Artisan-команда `aiqme:demo-export` (обёртка `bin/demo-build`) поднимает приложение с `APP_ENV=demo` и отдельной временной SQLite-БД, заполняет её `DemoSeeder` (заглушки и демо-заказы без реальных данных) и через HTTP-ядро Laravel в процессе рендерит список маршрутов: публичные LT/EN из таблицы маршрутов, экраны входа, кабинета и админки от имени демо-пользователей. Отдельный SPA или копия шаблонов не нужны: расхождение с основным сайтом минимально. Готовые пакеты статического экспорта Laravel можно рассмотреть, но совместимость с Laravel 13 не проверялась; простая собственная команда по списку маршрутов предпочтительнее.
- **Постобработка.** Ссылки и ресурсы переписываются под базовый путь Pages (`/<репозиторий>/`), маршруты сохраняются как `…/index.html`; в каждую страницу добавляются баннер «ДЕМО» на языке страницы и `meta robots noindex`; CSRF-токены и серверные `action` форм заменяются атрибутом `data-demo-form`. Небольшой `demo.js` перехватывает отправку и действия кабинета/админки и показывает «демо: данные не сохраняются» без сетевых запросов.
- **Калькулятор.** Используется тот же модуль ядра из W-10, он уже работает в браузере; серверный пересчёт (W-11) в демо не вызывается, итог помечается как ориентировочный.
- **Вывод и проверка.** Результат — `aiqme-site/demo/` (отслеживается Git: его раздаёт Pages; промежуточные файлы — в игнорируемом `aiqme-site/build/`). Проверки — по образцу `legacy-landing/scripts/check_github_pages_ui.py`: статусы страниц, отсутствие JS-ошибок и внешних запросов, пометка «ДЕМО» и `noindex` на каждой странице, поиск секретов и данных клиентов.
- **Публикация (D-16).** Весь корень публикуется в публичный репозиторий `GreatGleb/3d-fabrication-web`, Pages раздаёт его с корня ветки `main`. Демо открывается из папки: https://greatgleb.github.io/3d-fabrication-web/aiqme-site/demo/ (базовый путь сборки — `/3d-fabrication-web/aiqme-site/demo/`), так же как прежний лендинг из `legacy-landing/github-pages/`. Commit и push — только с явного разрешения; GitHub Actions не обязателен.
