# 9. Проверки и готовность

[← План](README.md). Все проверки бесплатные (В-010). Тест считается полезным, если ломается при контролируемой поломке (V-24-34 старого плана; перечень поломок итоговой проверки — W-21). Исторический PASS, мок и HTTP 2xx внешнего уровня не закрывают.

## 9.1. Набор `bin/check`

- `aiqme-site/bin/check`: Pint `--test` (только проверка; `experiments/` исключён); PHPUnit (Feature + Unit, PostgreSQL в Docker, БД с суффиксом `_test`, порт 55440); JS-тесты ядра калькулятора (включает W-10) — `node --test` без браузера и npm-пакетов; без node `bin/check` падает; Node стоит через nvm и может отсутствовать в `PATH` неинтерактивной оболочки, поэтому `bin/check` находит его явно и передаёт путь PHPUnit-тестам в `NODE_BINARY` (путь записан в `progress.md`); сборка Vite.
- `bin/browser-check` (отдельно): **Python Playwright** (`playwright.sync_api`, как `legacy-landing/scripts/check_github_pages_ui.py`; браузеры в `~/.cache/ms-playwright`) с bundled Chromium, не Chrome пользователя.
  - Своя БД `aiqme_browser` (миграции, сидер контента, данные задачи из фабрик; с W-12 — и `aiqme:bootstrap`). На каждый запуск сам создаёт администратора (`aiqme:make-admin --password-stdin`, D-29) и клиента со случайным паролем и входит ими в кабинет, админку и `/ru/` через форму входа (с W-07; до неё эти страницы — «пропущено»; служебных маршрутов входа нет).
  - Локальный сервер — через `bin/php` с лимитами §6.4 (у системного PHP 2M/8M). Режим `--base-url` (W-20) проверяет уже запущенный локальный prod-compose без подготовки БД и запуска сервера; принимает только `127.0.0.1`/`localhost` и проект `aiqme-prod`, рабочий сервер им не проверяется.
  - Запросы к любым хостам, кроме проверяемого, прерываются и перечисляются в отчёте (D-20; страница с Stripe Payment Element на уровне L — «не проверено до W-22»).
  - Проверяет ширину документа, меню и диалоги, нарушения CSP в консоли, маркеры D-21 (законные совпадения — только в `tests/fixtures/marker-allowlist.json`) и сверку оформления с эталоном через `getComputedStyle` ([§7.1](07-design.md#71-что-повторяем-точно)); кадры и отчёт сравнения — в игнорируемом `aiqme-site/build/verification/`.
- Lighthouse — `npx lighthouse@<версия>` с фиксированной версией (записана в `progress.md`) и `--chrome-path` на Chromium Playwright; если пакет недоступен без сети — «не проверено» с причиной.

## 9.3. Сквозные сценарии (уровень L, затем T)

1. Посетитель → контактная форма с 2 вложениями → письмо на info@aiqme.com → строка Requests → видна в админке.
2. Гость → калькулятор с 2 STL → заявка → секретная ссылка → администратор скачивает STL, подтверждает 150 EUR (120 + доставка) → запрос аванса 40 EUR → гость платит → производство при долге 110 EUR → запрос остатка → оплата → счёт → `shipped` с треком → `completed`; на каждом шаге строки Orders/Payments/Events. На уровне L оплата подаётся подписанными фикстурами в PHPUnit; в локальном prod-compose (W-20; администратор — `aiqme:make-admin --password-stdin`, D-29) сценарий проходит без шагов оплаты, тестовые адаптеры в production-образ не встраиваются.
3. Клиент: регистрация → заявка → отмена администратором после аванса → в карточке «оплачено 40 EUR, отменён», возврат не создан.
4. Восстановление пароля по письму; старые сессии завершены.
5. Администратор публикует проект в Telegram только на LT → виден на `/lt/`, 404 на `/en/`; публикует EN в вебе → появляется hreflang.

На уровне L сценарии 1–5 — Feature-тесты `tests/Feature/Scenarios/` задачи W-30 (оплата — подписанные фикстуры W-28, Sheets — фейк-сетка W-18 со строками на каждом шаге); W-21 переносит их итог в отчёт.

## 9.4. Уровни готовности функции

`L-готово` — тесты из 9.2 зелёные. `T-готово` — реальный тестовый вызов с записью в `aiqme-site/docs/verification/` (дата, тестовый объект, результат). `P-готово` — рабочий контрольный сценарий после явного разрешения. Статус «код готов, внешняя проверка заблокирована доступом» — промежуточный, не «готово».

## 9.5. Стоп-лист выпуска

Выпуск не открывается, если: возможен чужой доступ к заказу, файлу или счёту; деньги или номер счёта могут задвоиться; принятый заказ или файл может потеряться; неподтверждённый файл помечен готовым; демо или имитация выдаётся за рабочую функцию; секреты попали в репозиторий, логи или образ; в рабочей среде нет внешней копии и проверенного восстановления.
