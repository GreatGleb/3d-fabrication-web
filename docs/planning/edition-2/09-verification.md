# 9. Проверки и готовность

[← План](README.md). Все проверки бесплатные (В-010). Тест считается полезным, если ломается при контролируемой поломке (V-24-34 старого плана). Исторический PASS, мок и HTTP 2xx внешнего уровня не закрывают.

## 9.1. Набор `bin/check`

`aiqme-site/bin/check` запускает Pint (проверка), PHPUnit (Feature + Unit, БД PostgreSQL в Docker с суффиксом `_test`), JS-тесты ядра калькулятора (Node, без браузера), сборку Vite. Браузерные проверки — отдельно `bin/browser-check` (Playwright с bundled Chromium, не Chrome пользователя).

## 9.2. Обязательные содержательные тесты

| Область | Тесты |
|---|---|
| Ядро STL (JS и PHP одинаково) | ASCII и binary куб дают одинаковый объём; единицы mm/cm/in и масштаб (объём в кубе); обратная ориентация; открытый тетраэдр — предупреждение «незамкнутая сетка» (не молчаливый успех); усечённый файл, неверный счётчик, NaN/Infinity, 0 треугольников — отказ; граница 25 МиБ и 500 000 треугольников ровно/выше; контрольный пример `1 см³ PLA, 100 %, qty 1, 0,10 EUR/г, 5 EUR → 1,24 г, 5,124 EUR`; несколько файлов с платой за заказ и за файл; паритет JS ↔ PHP на корпусе фикстур |
| Заявка | Двойная отправка и две вкладки с одним токеном — один заказ; другой payload с тем же токеном — отказ; параллельные отправки — уникальные порядковые номера; гостевой заказ сохраняет контакты и файлы; сбой почты/Sheets не откатывает заказ; файл без записи не остаётся «сиротой» |
| Права | Клиент B и посетитель не видят заказ, STL, счёт и страницу оплаты клиента A по прямым ID и URL, включая HEAD/Range; неверный гостевой токен — 404; саморегистрация не даёт `is_admin`; клиент не может через HTTP подтвердить цену, задать сумму оплаты, начать производство; `/ru/` и админка без входа администратора — 404/вход |
| Цена и производство | Производство нельзя начать без подтверждённой цены; можно — без оплаты; цена не меняется после начала производства; изменение требует основания; уменьшение ниже оплаченного блокируется; открытый запрос блокирует изменение цены; отмена отменяет открытые запросы и не создаёт возврат; переходы только вперёд |
| Оплата | Сумма PaymentIntent только из запроса; повтор checkout — тот же intent (idempotency key); неподписанный, с чужим секретом, live в нетестовой среде — отказ; неверные сумма/валюта/intent/order — отказ; повтор события — без эффекта; `failed` → `succeeded` → поздний `failed` не отменяет оплату; два запроса (аванс + остаток) на один заказ складываются; переплата и оплата отменённого заказа записываются как `needs_review` и не теряются; webhook отвечает 200 на сохранённые аномалии; таймаут создания не создаёт второй intent; возврат браузера не ставит `paid`; `charge.refunded` уменьшает «оплачено» |
| Счета | Без реквизитов выпуск блокирован; номер выдаётся один раз при повторе события и параллельной обработке; повтор рендера не меняет номер; выпущенный PDF не меняется после правки профиля; чужой счёт недоступен |
| Контент | Публикация LT не публикует EN; EN-адрес материала без EN — 404, нет в sitemap/hreflang/поиске; заглушка исчезает после первой публикации и возвращается при снятии; устаревшая ревизия отклоняется в вебе и в Telegram; изменение видно на публичной странице сразу после публикации; RU только для администратора с `noindex` |
| SEO | Каждый публичный маршрут: 200, title/description, canonical, корректный hreflang, ссылки `<a href>`; неизвестный URL — 404; `/` → 301 `/lt/`; sitemap валиден и не содержит закрытых и RU-адресов |
| Формы | Валидная форма → запись + письмо (Mailpit) + событие Sheets; невалидная → ничего; honeypot не возвращает ложный успех с номером; вложения сверх лимита и не тех типов — понятная ошибка; ограничение частоты |
| Sheets | Повтор задания не дублирует строку; ручная сортировка или удаление строки не ломают upsert; формулы во вводе остаются текстом; пересборка не шлёт писем; 429 → повтор |
| Telegram | Чужой chat/user — отказ без данных; неверный `secret_token` — 401/403; повтор `update_id` — без эффекта; устаревшая кнопка не меняет другую запись; файл > 20 МБ — понятный отказ; правка из бота видна в вебе |
| Оформление | Ширина документа = окну на 320/390/768/1024/1440 для всех шаблонов LT и EN; меню и диалоги (Escape, `aria-expanded`, фокус); reduced-motion; расчёт работает без WebGL; сравнение с эталонными кадрами аудита (ручной просмотр расхождений, без порога pixel-diff) |
| Производительность | Lighthouse (бесплатный CLI) для главной, услуги, калькулятора LT/EN на мобильном профиле; разбор файла 25 МиБ в браузере не блокирует интерфейс без индикации и допускает отмену или повторный выбор |
| Эксплуатация | Миграции с нуля и с предыдущей версии; восстановление копии на чистую БД с проверкой хешей файлов; `.env.example` без секретов; в образе нет `instance/` и фикстур |

## 9.3. Сквозные сценарии (уровень L, затем T)

1. Посетитель → контактная форма с 2 вложениями → письмо на info@aiqme.com → строка Requests → видна в админке.
2. Гость → калькулятор с 2 STL → заявка → секретная ссылка → администратор скачивает STL, подтверждает 150 EUR (120 + доставка) → запрос аванса 40 EUR → гость платит → производство при долге 110 EUR → запрос остатка → оплата → счёт → `shipped` с треком → `completed`; на каждом шаге строки Orders/Payments/Events.
3. Клиент: регистрация → заявка → отмена администратором после аванса → в карточке «оплачено 40 EUR, отменён», возврат не создан.
4. Восстановление пароля по письму; старые сессии завершены.
5. Администратор публикует проект в Telegram только на LT → виден на `/lt/`, 404 на `/en/`; публикует EN в вебе → появляется hreflang.

## 9.4. Уровни готовности функции

`L-готово` — тесты из 9.2 зелёные. `T-готово` — реальный тестовый вызов с записью в `aiqme-site/docs/verification/` (дата, тестовый объект, результат). `P-готово` — рабочий контрольный сценарий после явного разрешения. Статус «код готов, внешняя проверка заблокирована доступом» — промежуточный, не «готово».

## 9.5. Стоп-лист выпуска

Выпуск не открывается, если: возможен чужой доступ к заказу, файлу или счёту; деньги или номер счёта могут задвоиться; принятый заказ или файл может потеряться; неподтверждённый файл помечен готовым; демо или имитация выдаётся за рабочую функцию; секреты попали в репозиторий, логи или образ; в рабочей среде нет внешней копии и проверенного восстановления.
