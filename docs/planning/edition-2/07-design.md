Основание: [визуальный отчёт аудита](../../customer-prototype/audit-20261016/visual-and-responsive.md), [наблюдения](../../customer-prototype/audit-20261016/observations.md), CSS прототипа — `docs/customer-prototype/evidence/audit-20261016/resources/3b84c1552d750b1f9d1d94c1ede102fc5cb443bf8e0b98963fb38cdd600aa5d8.css` (это `style.css`; ресурсы названы хешами, соответствие URL → файл — `resources.json`), снимок 15.10 — `docs/customer-prototype/evidence/20261015-214335/`. `evidence/` приватный (в `.gitignore`): его кадры и файлы в отслеживаемые файлы не копируются. ## 7.1. Что повторяем точно

- Шрифт `Arial, Helvetica, sans-serif` для всего сайта (вместо Ubuntu Sans в `legacy-landing/site/assets/site.css`); body 15 px / 1,6 (≤600 px — 14 px).
- Hero: h1 `clamp(54px, 5.1vw, 82px)`, line-height 1,06, letter-spacing −0,047em, weight 500, max-width 950 px; абзац «Skenuojame, projektuojame…» 21 px / 1,55, max-width 650 px, `#c2cad4`; ≤700 px — h1 52 px, абзац 18 px. Общие заголовки — weight 500, line-height 1,12, letter-spacing −0,045em. Значения из CSS сверяются по поздним правилам каскада: последние media-блоки ≤700 px перекрывают ранние ≤600 px.
- Токены: `#0867ff`, `#11171e`, `#64717e`, `#dce2e8`, `#f3f6f9`, `#0a1119`; контейнер 1320 px, поля 48 / 28 (≤1150) / 20 px (≤600); шапка 82 / 75 (≤900) / 68 px (≤600), второй ряд 39 / 38 px (≤600); кнопки ≥48 px, радиус 3 px; фокус — outline 3 px, отступ 4 px.
- Брейкпоинты: 1150 / 1050 / 900 / 760 / 700 / 600 и min-width 1440; сетки, каталог, калькулятор, кабинет и подвал — по [таблице аудита](../../customer-prototype/audit-20261016/visual-and-responsive.md#разные-классы-страниц).
- Светлый подвал (позднее правило CSS перекрывает раннее тёмное).

Разметка переписывается в Blade-компоненты. CSS прототипа переносится как основа (`resources/css/prototype/*.css`, D-19) с очисткой демо-классов, не «на глаз». Изображения прототипа (`/assets/*.png|jpg`, в том числе `url('/assets/engineering.jpg')` в CSS) в CSS не переносятся: ссылки заменяются заглушкой или удаляются. С 20.10 файлы, которые показывает прототип (логотип, favicon, ролик hero с постером, фото «О нас» и проектов, фрагменты иллюстраций услуг), выводятся как медиа по умолчанию из `aiqme-site/public/defaults/` до загрузки своих администратором ([D-43](decisions.md#d-43), W-33; логотип — D-25 → D-43).

**Как проверяется сходство без человека** (`bin/browser-check`, §9.1; провал сверки — провал задачи):

- **Стили.** Наши страницы снимаются в размерах `verified-route-screens.json`; `getComputedStyle` сверяет значения этого раздела: семейство и размеры шрифта, веса и межстрочные интервалы заголовков, цвета токенов (точно), высоты шапки и второго ряда, поля контейнера (±2 px).
- **Порядок блоков** — по отслеживаемому `aiqme-site/tests/fixtures/prototype-blocks.json`, один раз извлечённому в W-05 из `verified-route-screens/*/dom.html`: страница → упорядоченные прямые дети `main` как «тег + class» (`section.hero`, `section.section.dark`), без текстов. У элемента с классами `wrap` и `page-content` (на FAQ и политиках — `div.wrap.page-content.article`) берутся и его прямые дети (иначе на услугах, «О нас», FAQ и контактах сверялись бы только `page-top`, `page-content`, `cta-band`). Исключаются демо-блоки `div.notice` (контакты), `div.notice.warning` (политики) и блок команды `div.inset.gap` на «О нас» (D-21, D-32). На страницах услуг `div.section-head` примера («Application example») сверяется, только если у услуги есть опубликованный проект (без него `div.grid.two` с панелью «One point of contact…» остаётся — §4.1). Политики, пока черновики-заглушки (D-11), не сверяются. Blade-секции сохраняют классы прототипа. Эталон блоков есть только для страниц W-05; остальные шаблоны — только `getComputedStyle`.
- **Тексты** — каждая фраза видимого текста `main` эталона есть в нашем `main` в том же порядке; исключения — D-21, условные блоки без данных, страницы-черновики, `tests/fixtures/text-allowlist.json` (W-05, §9.2 «Контент»).
- **Кадры.** Отчёт «наш кадр рядом с эталоном» — в игнорируемый `aiqme-site/build/verification/`. В чистом клоне `evidence/` нет: отчёт пропускается с пометкой «не проверено (нет эталона)», а сверки стилей и порядка блоков выполняются. Ручной просмотр расхождений — «ждёт проверки пользователем»; порога pixel-diff нет.

## 7.3. Движение

- Hero-видео: muted, loop, playsinline, постер; отдельный MP4 для ≤700 px; файлы — медиа заказчика через медиабиблиотеку; до их загрузки — ролик и постер прототипа по умолчанию с подписью источника «Bosch / The Apic ↗» ([D-43](decisions.md#d-43), W-33). Автозапуск с учётом `document.hidden`, видимости (IntersectionObserver), reduced-motion и saveData; кнопка паузы; при ошибке — постер. Подпись источника со ссылкой — только если у медиа hero задан источник (`media`); у заглушки подписи нет, ссылки на чужой ролик без ролика тоже. Права на ролик Bosch / The Apic и другие референсы не установлены: до W-33 и в W-05 — заглушки (В-020); с 20.10 ролик прототипа — медиа по умолчанию, заменяется по первому требованию заказчика (D-43).
- Ленты брендов (38 s, ≤700 px — 32 s) и новостей (48 s) с паузой; при reduced-motion — статичный вид без дублей. Пока разделы на заглушке, ленты не нужны.
- Hover: кнопки поднимаются на 1 px за 0,18 s, карточки услуг — на 4 px за 0,2 s.
- Эффекты V2 (мозаика, маски фото, длинные закреплённые сцены, плавающий CTA, вертикальные услуги, подвижная подложка навигации) **не переносятся**: в прототипе их нет.
- «СКАН → CAD → ДЕТАЛЬ» (`legacy-landing/design-previews/animation-v2/assets/gear.js`, `scene.html`): исходники сохраняются; сцена ставится только в блок прототипа, совпадающий по смыслу и размеру, новой секции нет. Такого блока нет (строка hero «01 SCAN → 02 DESIGN → 03 MANUFACTURE» — текст, а `gear.js` — закреплённая сцена прокрутки), поэтому в MVP сцена не выводится (D-40, W-05). Русские строки V2 в публичные версии не попадают. Отменённая крыльчатка не возвращается.

## 7.5. Устройства

Телефоны, планшеты, ноутбуки и настольные компьютеры (В-022). Проверка — эмуляция в отдельном Chromium (Playwright bundled), не в Chrome пользователя: 320×568, 390×844, 768×1024, 1024×768, 1440×1000, 844×390. Реальные устройства не проверялись. WCAG 2.2 AA — ориентир: семантика, клавиатура, контраст, масштаб 200 %, reflow 320 px; формального заявления о соответствии нет. Озвучивание и системные флаги доступности не включаются.
