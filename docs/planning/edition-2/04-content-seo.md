# 4. Контент, переводы, SEO, Telegram

[← План](README.md). Согласовано: общая база контента для веб-админки и личного Telegram-бота; оба интерфейса редактируют страницы, тексты, услуги, проекты, новости, обучение, товары, фото, видео и переводы; общие права и правила публикации; обновление без изменения кода и пересборки; без конструктора страниц; одобренные изменения появляются в пределах часа (В-044–В-051, [requirements](../../requirements.md#уточнения-управления-и-уведомлений-в-044в-059-в-072)).

## 4.1. Модель контента

| Тип | Поля (на каждую локаль, если не указано) | Где показывается |
|---|---|---|
| `page_text` | Фиксированный набор блоков страницы, заданный в коде (заголовок hero, абзац, CTA, процесс, блоки «О нас», контакты, тексты политик) | Главная, о нас, контакты, политики |
| `ui_text` | Ключ → строка (меню, подвал, кнопки, ошибки, тексты форм) | Везде; значения по умолчанию — из языковых файлов, база их переопределяет |
| `service` | Название, slug, описание, проблема, исходные материалы, результат, процесс, пример, FAQ, SEO title/description, порядок, иллюстрация | Услуги, главная |
| `project` | Название, slug, задача → решение → результат, связанные услуги, применение, фото, YouTube-ссылка, SEO | Проекты |
| `article` | Раздел (новости / библиотека), категория, материал, название, slug, текст, дата, SEO | Информация, новости, библиотека, главная |
| `training` | Название, slug, описание, дата, формат (online / в AIQME / у клиента), SEO | Обучение |
| `product`, `brand`, `category` | Товар: название, slug, категория, бренд, цена для показа, характеристики, совместимость, описание, фото. Бренд: название, логотип, ссылка. Категория: название LT/EN | Товары, сравнение, бренды на главной |
| `faq_item` | Вопрос, ответ, группа | FAQ, услуги |
| `media` | Файл (spatie/medialibrary), alt/подпись на локаль, назначение; для видео — постер и мобильный вариант | Везде |

Изменение структуры блоков — разработка; администратор меняет содержимое, но не макет.

## 4.2. Языки и публикация

- Локали `lt`, `en` публичные; `ru` — тестовая. У перевода свои slug, поля, SEO и `published_at`.
- **Публикация по каждому языку отдельно.** Материал без опубликованного EN не показывается под `/en/`: 404 для карточки, отсутствие в списках, поиске, sitemap и hreflang. LT-текст под EN-адресом не подставляется (В-017). Отсутствующий `ui_text` на EN берётся из EN-файла языка, а не из LT.
- **Заглушки.** Бренды, товары и новости по умолчанию показывают «Informacija ruošiama» / «Information is being prepared». Как только в разделе появляется хотя бы одна опубликованная запись на этой локали, показывается контент. Кода и пересборки это не требует. Те же механизмы применяются к проектам и политикам, если по D-11 их демо-тексты не публикуются.
- **Черновик и опубликованная версия.** Сохранение не публикует. «Опубликовать (LT/EN)» делает текущую версию видимой; «Снять с публикации» скрывает её. Предыдущие версии хранятся (`content_revisions`), восстановление старой создаёт новую версию.
- **Срок появления.** Страницы рендерятся из БД, кэш HTML публичных страниц сбрасывается при публикации; верхний предел кэша — 10 минут. Целевой час (В-051) выполняется с запасом.
- **Одновременная правка** в вебе и Telegram (В-050 — простой вариант): каждое сохранение передаёт ожидаемую ревизию. При расхождении сохранение отклоняется с сообщением «изменено в другом окне», введённый текст не теряется (в вебе он остаётся в форме, в Telegram бот показывает обе версии). Правило «последняя запись побеждает» молча не применяется.
- Произвольный HTML и JS через редакторы не допускаются: текст — Markdown-подмножество или санитизированный HTML с белым списком тегов.
- Исходное наполнение (D-11): тексты услуг, главной, «О нас», FAQ и 3 статей импортируются из `data.js`/DOM прототипа (LT и EN, с исправлением EN-проектов). Демо-товары, демо-новости, демо-бренды, демо-цены и пометки «demo» не импортируются.

## 4.3. Тестовый русский `/ru/`

- Маршруты `/ru/…` существуют, только пока вошёл администратор. Остальным — 404; скрытый URL защитой не считается.
- `X-Robots-Tag: noindex, nofollow` и `<meta name="robots">`; нет в sitemap, hreflang и публичном переключателе.
- Переводы RU редактируются теми же редакторами; отсутствие RU-перевода ничего не блокирует.

## 4.4. SEO и производительность

| Требование | Реализация |
|---|---|
| Готовый HTML с сервера | Blade-рендер содержимого, метаданных и обычных ссылок; JS только улучшает |
| HTTP-статусы | 200, 301 (`/` → `/lt/`, смена slug → новый slug), 404, 410 не нужен; поиск, кабинет, админка, оплата — `noindex` |
| Метаданные | `<title>` и description из SEO-полей перевода, иначе из заголовка и вводного абзаца (исправление F-45); Open Graph — заголовок, описание, изображение |
| canonical | Самоссылка на опубликованный URL локали |
| hreflang | Только между опубликованными LT/EN-версиями одной сущности, взаимно; `x-default` → LT-версия |
| sitemap.xml | Динамический: все опубликованные страницы LT/EN с alternates; без RU, кабинета, админки, поиска и пустых разделов-заглушек |
| robots.txt | Ссылка на sitemap; закрытые разделы не закрываются `Disallow`, если там нужен `noindex` |
| Изображения | Медиабиблиотека генерирует WebP-варианты нескольких ширин; `srcset/sizes`, `width/height`, `loading=lazy` ниже первого экрана, `alt` из подписи |
| Видео | Постер, отдельный мобильный MP4 (≤700 px, как в прототипе), `preload=metadata`, пауза вне экрана, reduced-motion и saveData |
| Ресурсы | Vite с хешами, долгий кэш статики, gzip/brotli на веб-сервере; шрифты не загружаются (Arial-стек) |
| Закрытые данные | Кабинет, заказы, файлы, счета, гостевые ссылки никогда не попадают в sitemap и в публичный HTML |

## 4.5. Telegram-бот (контент)

- Только **личный чат** единственного администратора. Привязка: в админке «Integrations → Telegram → получить код»; администратор отправляет боту `/start <код>`; код одноразовый, живёт 10 минут. Сохраняется Telegram `user.id` и `chat.id`. Username, имя и членство в группах прав не дают. Сообщения из других чатов и от других пользователей отклоняются без раскрытия данных.
- Webhook с `secret_token` (заголовок `X-Telegram-Bot-Api-Secret-Token`), дедупликация по `update_id`, ответ 200 после сохранения апдейта.
- Команды над `ContentService` (те же правила, что в вебе): выбрать тип → выбрать запись или создать → выбрать поле и язык → ввести текст → предпросмотр → сохранить черновик → опубликовать/снять для LT или EN. Inline-кнопки несут id записи и ревизию; устаревшая кнопка отклоняется. Контекст диалога хранится на сервере с ограниченным сроком; `edited_message` не применяется как новая команда.
- Медиа: фото или видео в чат с подписью или в контексте записи → загрузка в медиабиблиотеку и привязка. **Ограничение Bot API:** бот может скачать файл до 20 МБ. Большее видео загружается через веб-админку — бот так и отвечает.
- Удаление записей через бот не делается: только снятие с публикации. Удаление выполняется в вебе.
- Заказы, клиенты и платежи в боте не показываются: они в веб-админке и Google Таблицах (В-046/047). Имитатор чата в админке не нужен.
- Сбой Telegram не отменяет сохранённую правку. Отправка ответа бота — после commit.
