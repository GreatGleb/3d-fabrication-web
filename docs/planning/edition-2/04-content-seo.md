# 4. Контент, переводы, SEO, Telegram

[← План](README.md). Согласовано (В-044–В-051, [requirements](../../requirements.md#уточнения-управления-и-уведомлений-в-044в-059-в-072)): одна база контента для веб-админки и личного Telegram-бота; оба редактируют страницы, тексты, услуги, проекты, новости, обучение, товары, фото, видео и переводы по общим правам и правилам публикации; без изменения кода, пересборки и конструктора страниц; одобренное появляется в пределах часа.

## 4.1. Модель контента

| Тип | Поля (на каждую локаль, если не указано) | Где показывается |
|---|---|---|
| `page_text` | Фиксированный в коде набор блоков страницы (hero, абзац, CTA, процесс, блоки «О нас», контакты, вводный текст обучения, тексты политик) | Главная, о нас, контакты, обучение (вводный текст публикуется; черновики — только элементы `training`), политики |
| `ui_text` | Ключ → строка (меню, подвал, кнопки, ошибки, формы) | Везде; по умолчанию — языковые файлы, база их переопределяет |
| `service` | Название, slug, `short` (подзаголовок страницы услуги и результат поиска), подпись и три пункта блока услуги (главная и список услуг), описание, проблема, исходные материалы, результат, SEO title/description, порядок, иллюстрация. Своих полей «процесс», «пример», FAQ нет: процесс — общий `page_text` главной (правка D-21 действует и здесь); пример — карточка опубликованного проекта с этой услугой, без него заголовок примера и карточка не выводятся, а панель «One point of contact…» (`ui_text`) выводится всегда; FAQ — `faq_item` группы услуги и группы `services`; у услуги обучения — блок тем и дат (опубликованные `training` или заглушка, §1.2) | Услуги, главная |
| `project` | Название, slug, задача → решение → результат, связанные услуги, применение, фото, YouTube-ссылка, SEO | Проекты |
| `article` | Раздел (новости / библиотека), категория, название, slug, текст, дата, SEO (3 статьи прототипа — «библиотека», W-04) | Списки: информация, новости, библиотека, главная (только «новости», D-26). Карточка любой статьи — `/lt/biblioteka/<slug>/` · `/en/library/<slug>/`, как в прототипе (`/naujienos/<slug>/` — 404); раздел влияет только на списки |
| `training` | Название, описание, дата, формат (online / в AIQME / у клиента); без slug и SEO: детальной страницы нет (запись в списке, регистрация — модалка W-09), SEO — у `page_text` страницы обучения | Обучение |
| `product`, `brand`, `category` | Товар: название, slug, категория, бренд, цена для показа, характеристики, совместимость, описание, фото. Бренд: название, логотип, ссылка. Категория: название LT/EN, slug (5 категорий прототипа импортируются опубликованными — навигация главной, W-04) | Товары, сравнение, бренды и категории на главной |
| `faq_item` | Вопрос, ответ, группа: slug услуги; `services` — общий вопрос всех страниц услуг «Nuo ko priklauso terminas?» · «What determines the lead time?»; `general` — только вопросы страницы FAQ, которых нет в FAQ услуг («Do I need an account to order?», «Can I collect in person?»). Единственное место хранения FAQ, без копий | FAQ (группы услуг в порядке услуг, затем `general`, без `services` — 8 вопросов, как в прототипе); страница услуги (её группа, затем `services`) |
| `media` | Файл (spatie/medialibrary), alt/подпись на локаль, назначение; для видео — постер и мобильный вариант; необязательный источник (текст и ссылка; подпись источника hero, §7.3) | Везде |

Изменение структуры блоков — разработка; администратор меняет содержимое, не макет.

## 4.2. Языки и публикация

- Локали `lt`, `en` публичные; `ru` — тестовая. У перевода свои slug, поля, SEO и `published_at`.
- **Публикация по каждому языку отдельно.** Без опубликованного EN материала нет под `/en/`: карточка 404, нет в списках, поиске, sitemap и hreflang. LT-текст под EN-адресом не подставляется (В-017). Отсутствующий EN `ui_text` берётся из EN-файла языка, не из LT.
- **Заглушки.** Бренды, товары и новости по умолчанию показывают «Informacija ruošiama» / «Information is being prepared»; с первой опубликованной записью на этой локали показывается контент, без кода и пересборки. То же для проектов и политик, пока их демо-тексты не опубликованы (D-11).
- **Черновик и публикация.** Сохранение не публикует. «Опубликовать (LT/EN)» делает текущую версию видимой, «Снять с публикации» скрывает. Версии хранятся (`content_revisions`); восстановление старой создаёт новую версию.
- **Срок появления.** Кэша HTML нет: страницы рендерятся из БД на каждый запрос, правка видна сразу (В-051 с запасом). Кэш целой страницы несовместим с nonce CSP и CSRF-токеном (§6.6) и не нужен при текущей нагрузке; если понадобится — отдельной задачей и только для гостей без сессии.
- **Одновременная правка** в вебе и Telegram (В-050): сохранение передаёт ожидаемую ревизию; при расхождении оно отклоняется с сообщением «изменено в другом окне», текст не теряется (в вебе остаётся в форме, бот показывает обе версии). «Последняя запись побеждает» молча не применяется.
- Произвольный HTML/JS через редакторы запрещён: Markdown-подмножество или санитизированный HTML с белым списком тегов.
- **Исходное наполнение (D-11), результат — отслеживаемый `database/seeders/data/prototype-content.json` (W-04):**
  - источники: услуги (с FAQ → `faq_item` группы услуги), 3 статьи и проекты — `data-from-source.json` аудита; главная, «О нас», общий FAQ (`general`), общий вопрос услуг (`services`), контакты, обучение, 4 политики — видимый текст `verified-route-screens/<маршрут>/dom.html` (в `data-from-source.json` их нет); LT и EN, EN-проекты исправляются;
  - только тексты, без разметки и `dom.html` (D-19); черновики (политики, проекты, темы и даты обучения) — дословно; в публикуемых текстах правятся только фразы таблицы D-21; надписи оболочки прототипа — не контент (W-03); служебные демо-надписи шаблонов не переносятся (D-21; поиск маркеров `bin/browser-check` из W-03 — в каждой задаче с шаблонами, итог — W-21);
  - заметки автора прототипа о непредоставленных данных (блок команды «О нас», панель техдокументов, фраза карточки статьи) не переносятся (D-21, D-32); демо-товары, -новости, -бренды, -цены, пометки «demo» и медиа третьих лиц не импортируются.
- **Строки интерфейса и шаблонов** (`lang/lt|en/*.php`, значения `ui_text` по умолчанию) — по [tasks.json](tasks.json) `rules` (источники текстов прототипа, D-19/D-21).

## 4.3. Тестовый русский `/ru/`

- Маршруты `/ru/…` существуют, только пока вошёл администратор; остальным — 404 (скрытый URL защитой не считается).
- Сегменты — английские под префиксом `/ru/` (`/ru/services/…`); slug сущности — из RU-перевода, без него страница RU — 404.
- `X-Robots-Tag: noindex, nofollow` и `<meta name="robots">`; нет в sitemap, hreflang и публичном переключателе.
- RU редактируется теми же редакторами; отсутствие RU ничего не блокирует.
- Без RU-значения статические тексты и интерфейс берутся из EN (`fallback_locale = en`): администратор видит EN-значения `ui_text`/`page_text`, не ключи.

## 4.4. SEO и производительность

| Требование | Реализация |
|---|---|
| Готовый HTML с сервера | Blade-рендер содержимого, метаданных и обычных ссылок; JS только улучшает |
| HTTP-статусы | 200, 301 (`/` → `/lt/`), 404; 410 не нужен; смена slug — старый адрес 404 (истории slug и перенаправлений нет); поиск, кабинет, админка, оплата — `noindex` |
| Метаданные | `<title>` и description из SEO-полей перевода, иначе из заголовка и вводного абзаца (F-45); Open Graph — заголовок, описание, изображение |
| canonical | Самоссылка на опубликованный URL локали в виде, который генерирует `route()` (без завершающего «/»); canonical, hreflang, sitemap и внутренние ссылки — только через `route()`; адрес со «/» (как в прототипе) отвечает тем же содержимым с тем же canonical (W-02) |
| hreflang | Только между опубликованными LT/EN-версиями одной сущности, взаимно; `x-default` → LT |
| sitemap.xml | Динамический: опубликованные страницы LT/EN с alternates; без RU, кабинета, админки, поиска и пустых разделов-заглушек |
| robots.txt | Ссылка на sitemap; разделы, где нужен `noindex`, не закрываются `Disallow` |
| Изображения | WebP-варианты нескольких ширин; `srcset/sizes`, `width/height`, `loading=lazy` ниже первого экрана, `alt` из подписи |
| Видео | Постер, отдельный мобильный MP4 (≤700 px), `preload=metadata`, пауза вне экрана, reduced-motion и saveData |
| Ресурсы | Vite с хешами, долгий кэш статики, gzip/brotli; шрифты не загружаются (Arial-стек) |
| Закрытые данные | Кабинет, заказы, файлы, счета, гостевые ссылки — никогда в sitemap и публичном HTML |

## 4.5. Telegram-бот (контент)

- Только **личный чат** единственного администратора. Привязка: админка «Integrations → Telegram → получить код» → администратор отправляет боту `/start <код>`. Код одноразовый, 10 минут, ≥128 бит случайности в base64url (deep-link `t.me/<бот>?start=<код>` — до 64 символов `[A-Za-z0-9_-]`); хранится только SHA-256; неверные попытки ограничены по `user.id` и ничего не раскрывают. Сохраняются `user.id` и `chat.id`; username, имя и членство в группах прав не дают. Другие чаты и пользователи отклоняются без раскрытия данных.
- Webhook с `secret_token` (заголовок `X-Telegram-Bot-Api-Secret-Token`), дедупликация по `update_id`, ответ 200 после сохранения апдейта.
- Команды над `ContentService` (правила те же, что в вебе): тип → запись или новая → поле и язык → текст → предпросмотр → черновик → опубликовать/снять LT или EN. Inline-кнопки несут id записи и ревизию; устаревшая кнопка отклоняется. Контекст диалога — на сервере с ограниченным сроком; `edited_message` не применяется как новая команда.
- Медиа: фото или видео с подписью или в контексте записи → медиабиблиотека и привязка. **Bot API скачивает файлы только до 20 МБ**; большее видео — через веб-админку, бот так и отвечает.
- Удаления через бот нет — только снятие с публикации; удаление — в вебе.
- Заказы, клиенты и платежи в боте не показываются (они в веб-админке и Google Таблицах, В-046/047). Имитатор чата в админке не нужен.
- Сбой Telegram не отменяет сохранённую правку; ответ бота — после commit.

## 4.6. Ожидаемые статусы адресов прототипа

Тесты W-02, W-06, W-25, W-07/W-15, W-08 и демо-сборка W-24 сверяют все 184 адреса [route-manifest](../../customer-prototype/audit-20261016/routes.md) с этой таблицей (а не правило «все маршруты отвечают») через отслеживаемый `aiqme-site/tests/fixtures/prototype-routes.json`: его один раз извлекает W-02 (только путь и ожидаемый статус/строка таблицы, без текстов), потому что `evidence/` в чистом клоне нет. Адрес манифеста без строки здесь — ошибка теста.

Порядок по задачам: W-02 — статические страницы, 301 и строки с 404 (кроме slug сущностей); W-05/W-06/W-25 — адреса сущностей после сидера W-04 (slug из БД, не зашиты в маршруты); W-07/W-15 — кабинет (`invoices` W-15 создаёт пустой, список наполняет W-17); админка — каждая задача только свои вкладки (W-08 — оболочка, заготовка `overview`, `services`, `content`, `audit`; W-26 — `products`, `categories`, `projects`, `training`, `translations`; W-11 — `calculator`; W-14 — `overview`, `orders`, `customers`; W-17 — `settings`; W-18 — `integrations`, W-19 добавляет привязку Telegram); полностью — W-21.
