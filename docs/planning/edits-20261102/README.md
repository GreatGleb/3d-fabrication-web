## Решения пользователя 02.11

- **Калькулятор — полностью по макету 17.09.** Параметры задаются у каждого файла. У каждого файла есть
  «Gamybos būdas»: 3D spausdinimas, Frezavimas или Graviravimas. Принимаются DXF и DWG. Цену STEP, OBJ, DXF, DWG и
  всё, что не печатается из STL, назначает специалист, как сейчас при подтверждении цены.
- **Второй ряд шапки** (`header-cta`: «3D INŽINERIJA IR TECHNOLOGIJOS» и «Įkelti modelį ir sužinoti kainą») убирается
  **только на главной**. На остальных страницах он остаётся.
- **RU в админке.** Поля и строка публикации RU скрываются из редакторов. Русская версия `/ru/` для вошедшего
  администратора остаётся (решение требований), без редактора она берёт тексты из lang-файлов и EN.
- **Счёт — по образцу заказчика.**
  - Домен и почта — **aiqme.com** (`info@aiqme.com`), а не aiqme.eu из образца. Они, как и телефон, берутся из
    настроек продавца.
  - Банк, SWIFT и IBAN — как в образце; значения вписываются в настройки при выпуске (G-10), в коде их нет.
  - **Нумерация — отдельная серия сайта `AIQW`, номер из 5 цифр с ведущими нулями: `AIQW00001`, `AIQW00002`…**
    Образец `AIQ60004` выписан бухгалтерской программой заказчика. Если сайт продолжит ту же серию, номера
    столкнутся с ручными счетами: сайт не знает, какой номер программа выдала последним. Отдельная серия на каждый
    канал продаж — обычная практика, и каждая серия идёт подряд без пропусков. Серия и начальный номер — уже
    существующие настройки `series` / `first_number`; при выпуске ставится `AIQW` и `1`. Тестовые счета `AIQ-1`,
    `AIQ-2` на aiqme.com остаются как были.
  - Для оплаченного заказа вместо «Apmokėti iki» и пени пишется «Apmokėta».

## Что не входит в очередь (сознательно)

- **Админка заказов в Telegram.** Заказчик хотел бы управлять заказами в боте; пользователь отложил это до потока
  заказов. Бот по-прежнему только для правки контента.
- **Аватар бота.** Квадрат вокруг логотипа на видео заказчика — это не бот, а шапка сайта (Г1). Аватар бота меняет
  человек через BotFather, если понадобится, — квадратной картинкой со сплошным фоном. В код это не входит.
- **Документы у товара и на «Informacija»** («Informacija ruošiama»). Заказчик спросил, где их заполнять. Загрузки
  документов в админке нет, это новая функция; пользователь объяснит заказчику, правки здесь нет.
- **Поле даты `mm/dd/yyyy`** в контактной форме. Это формат браузера; заказчик о нём не писал.
- **Отличия макетов, не отмеченные заказчиком**: в шапке нет значков языка и корзины, «PRELIMINARI INFORMACIJA»
  вместо «PRELIMINARI SĄMATA», «Įkelti modelius dar kartą» во втором ряду, переключатель «Tie patys parametrai
  visiems modeliams» (был только в первом макете 16.14 и пропал в 17.09). Всё остаётся как сейчас.

### Миграции контента (Г1 п. 4 и Г2)

Контент в БД сидер не перезаписывает (`PrototypeContentSeeder` добавляет только отсутствующее), а на aiqme.com
тексты уже лежат в БД. Поэтому для каждого изменённого поля:
1. меняется `prototype-content.json` — для новых установок;
2. пишется одна миграция данных по образцу `2026_10_29_000000_set_calculator_max_dimension_1000.php`: значение
   меняется, только если в БД всё ещё прежний текст (правку администратора не трогать, в progress.md —
   «не изменено: отредактировано администратором», если так); `down` возвращает прежний текст при том же условии.

Опубликованная и черновая версии меняются одинаково — по тому, как они хранятся (посмотреть модель контента).

**Проверки.** Тест миграции: старый текст меняется на новый, отредактированный не меняется, `down` возвращает.
Страницы `/lt`, `/en`, `/lt/paslaugos/3d-spausdinimas`, `/en/services/3d-printing` показывают новые тексты, блока

## Г3. Формы (G-03)

1. **Флажок капчи не виден до проверки** (снимок 14.25: только «Aš nesu robotas»; после проверки — зелёный флажок).

   **Как должно стать.** В `shell.css` у `altcha-widget` заданы явные цвета без `light-dark()`: рамка флажка
   `#8a99ab` (не светлее, чтобы был контраст ≥3:1 к белому), фон белый, цвет текста. Флажок виден до проверки во
   всех браузерах проверки. Сначала проверить в bundled Chromium: если рамка видна и там, причину искать дальше (в
   `bin/browser-check` есть кадр формы) и записать найденное в progress.md.
2. **«Choose Files / No file chosen»** (снимок 18.10) — стандартный выбор файла в контактной форме
   (`public/contact.blade.php:52`, `attachments[]`, multiple).

   **Как должно стать.** Своё оформление по образцу загрузки калькулятора (`calculator.blade.php:29-35`: `label`,
   скрытое `sr-only` поле, кнопка `.btn`):
   - кнопка «Pasirinkti failus» / «Choose files»;
   - под ней список выбранных имён или «Failas nepasirinktas» / «No file selected»;
   - небольшой скрипт в `resources/js/` обновляет список по `change`;
   - без JS поле работает как обычное.

   Подпись поля, `accept`, лимиты и серверная проверка не меняются. Поле остаётся доступным с клавиатуры, фокус

   страница открывается сверху, и его легко не заметить.
