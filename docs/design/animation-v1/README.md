# Проверка отдельной анимационной версии

30 сентября 2026. Новая версия собрана отдельно; основной сайт не заменён.

Запуск, устройство и возврат: [инструкция варианта](../../../legacy-landing/design-previews/animation-v1/README.md).

## Результаты

- Контрольные суммы 96 файлов обычного сайта и его сборок совпадают со снимком до изменений.
- Проверены десктоп 1440×900, телефон 390×844, планшет 768×900, низкое окно 1440×600, reduced motion и отключённый JavaScript.
- Закреплённая сцена корректно проходит скан → CAD → готовая деталь и возвращается к скану при прокрутке назад.
- Проверены изменение размера окна, включение reduced motion во время просмотра, обычный поток и переключение версий на текущем разделе.
- Вариант прошёл существующие `check_pages.check()`, `check_demo.check()` и `check_ui.check()`. Проверки запускались с переопределением OUTPUT на `build/motion-v1/animated`, а ROOT — на временный каталог, чтобы сохранить существующие сборки и отчёты.
- Проверены страницы под вложенным адресом, отсутствие внешних запросов и запросов API в демо, калькуляторы, формы, файлы, клавиатура и адаптивность на девяти ширинах от 360 до 1440 px.

Автоматический отчёт: [checks.json](checks.json). Результат существующих проверок: [regressions.txt](regressions.txt).

## Проверка исправленных эффектов

После замечаний пользователя добавлена отдельная проверка фактической геометрии движения: [effects-check.json](effects-check.json), запуск `python3 scripts/check_motion_effects.py`. На 390, 768 и 1440 px проверены главный рисунок, три заголовка, карточки услуг и проектов, текст «О нас», стрелки, закреплённая шапка и три кадра кейса. Подъём заголовков и карточек составляет 64 px. На узких экранах теперь работает компактная закреплённая панель кейса; показ всех кадров обычным потоком сохраняется при reduced motion, без JS, в коротком окне и при выборе flow.

Причина потери подъёма: переход работал уже при назначении начальной скрытой позиции; при раннем входе в экран обратное движение начиналось с промежуточного смещения. Теперь переход назначается только видимому состоянию. Hero ожидает декодирования и видимости изображения. Для кеша CSS/JS используются версии по хешу содержимого.

Снимки после исправлений: [компьютер](fixed-1440.png), [планшет](fixed-768.png), [телефон](fixed-390.png). Проверки выполнены в Chrome с эмуляцией размеров; физические мобильные устройства не проверялись.

Дополнительно проверены меню с эмуляцией сенсорного ввода на 390/768 px и выбор STL с клавиатуры после удаления файла в обоих калькуляторах, в обычной и анимационной версии. Первый общий прогон UI остановился по таймауту filechooser; отдельная проверка этого сценария прошла на обеих версиях.

Повтор полного UI-прогона также завершился таймаутом filechooser после серии адаптивных переходов. При отдельном запуске интерактивной части с одной шириной (390 px) все проверки файлов, устаревших чтений, клавиатуры, ошибок формы и no-JS прошли в анимационной и обычной версиях. Причина зависимости полного прогона от предшествующих переходов не установлена; общий UI-прогон не объявляется успешным. Проверки эффектов, demo и motion-preview прошли отдельно.
