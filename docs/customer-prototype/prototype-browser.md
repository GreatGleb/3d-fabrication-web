# Просмотр прототипа AIQME через Chrome пользователя

Проверено 15 октября 2026: [литовская страница прототипа](https://aiqme-engineering-prototype.aiqme-9193.chatgpt.site/lt/)
доступна в существующей сессии Chrome пользователя. Основной способ работы —
Playwright через Chrome DevTools Protocol (CDP). Он позволяет читать DOM,
вычисленные стили, загруженный CSS/JS и делать скриншоты.

## Начало работы в новой сессии

1. Прочитайте эту инструкцию и [актуальные требования](../requirements.md).
   Для изучения уже сохранённой версии достаточно файлов снимка ниже; новое
   подключение нужно для актуального состояния и проверки поведения.
2. Используйте работающий Chrome пользователя, где есть доступ к прототипу.
   Не запускайте отдельный чистый профиль и не перезапускайте его браузер.
   При необходимости откройте вкладку командой:

   ```bash
   google-chrome --profile-directory=Default 'https://aiqme-engineering-prototype.aiqme-9193.chatgpt.site/lt/'
   ```

   В проверенной сессии профиль `Default` называется `Gleb`. Если окружение
   изменилось, не считайте это универсальным именем профиля.
3. Проверьте наличие `~/.config/google-chrome/DevToolsActivePort`.
   Если подключение уже работает, повторно просить пользователя включать его не нужно.
   Если отладка выключена, пользователь включает её в
   `chrome://inspect/#remote-debugging`. При соединении Chrome может показать
   `Allow remote debugging?` — нужно разрешить подключение.
4. Из корня проекта выполните:

   ```bash
   python3 docs/customer-prototype/tools/capture_prototype_chrome.py
   ```

   Нужны Python и Playwright из `legacy-landing/requirements-dev.txt`. Используется установленный
   Chrome пользователя, отдельная установка браузера Playwright для этого не нужна.
   Скрипт ожидает подключение до 120 секунд. Не запускайте несколько ожидающих
   подключений одновременно: они могут создать несколько диалогов разрешения.
5. Скрипт напечатает путь нового каталога и манифест. Откройте PNG инструментом
   просмотра изображений: наличие файла само по себе не подтверждает, что на нём
   нужная страница. Проверьте URL, заголовок, HTTP-статусы и отсутствие `error`
   у ресурсов в `manifest.json`.

Можно задать новый, ещё не существующий каталог:

```bash
python3 docs/customer-prototype/tools/capture_prototype_chrome.py --output docs/customer-prototype/evidence/manual-check-01
```

## Что сохраняется

По умолчанию создаётся `docs/customer-prototype/evidence/YYYYMMDD-HHMMSS/`.
Старые снимки не перезаписывать: это свидетельства состояния на момент проверки.

| Файл | Содержимое |
|---|---|
| `viewport.png` | Первый экран при viewport 1440×1000. |
| `full-page.png` | Скриншот всей страницы. Ширина может отличаться из-за полосы прокрутки. |
| `dom.html` | DOM после выполнения JavaScript. |
| `resources/*.html` | Исходные ответы HTML. |
| `resources/*.css`, `resources/*.js` | Полные тела загруженных ответов CSS/JS, имена по SHA-256. |
| `manifest.json` | Соответствие URL → файл, HTTP-статус, размер, SHA-256, шрифты и размеры страницы. |

Скрипт открывает отдельную вкладку в контексте, где уже открыт прототип, затем
закрывает только свою вкладку. Не выгружает cookies, пароли или заголовки запросов.
Он сохраняет ресурсы, загруженные при открытии `/lt/`, а не серверные исходники
или весь сайт. Картинки, видео и шрифтовые файлы отдельно не скачиваются.
Не посещённые маршруты и не загруженные ленивые модули не входят в снимок.
Скриншот всей страницы не доказывает загрузку всех элементов, появляющихся при прокрутке;
их проверяйте отдельным просмотром и прокруткой.

## Интерактивное исследование и код

Для новых проверок используйте тот же способ соединения, что в
[`capture_prototype_chrome.py`](tools/capture_prototype_chrome.py):

- Прочитайте две строки `DevToolsActivePort`: порт и путь WebSocket. Подключитесь
  через `chromium.connect_over_cdp(f"ws://127.0.0.1:{port}{endpoint}")`.
  Не фиксируйте UUID WebSocket в коде или документации: он меняется.
- Найдите контекст по вкладке с доменом прототипа. Создайте свою вкладку для
  навигации, проверки ссылок, меню, адаптивной вёрстки и прокрутки.
- Читайте текст через локаторы, DOM через `page.content()`, вычисленные стили
  через `page.evaluate()` и `getComputedStyle()`. Сохраняйте снимки через
  `page.screenshot()`. Чтение кода начинайте с соответствия URL → файл в манифесте.
- После работы закройте свою вкладку и отключите клиент Playwright.
  Не вызывайте `browser.close()` для браузера пользователя.
- Просмотр не означает отправку форм, создание заказов или изменение данных.
  Отличайте демонстрационные элементы прототипа от работающей серверной функции.

Проверенный снимок: [манифест](evidence/20261015-214335/manifest.json),
[первый экран](evidence/20261015-214335/viewport.png),
[вся страница](evidence/20261015-214335/full-page.png).
В нём сохранены `style.css` (43 286 байт), `data.js` (22 483 байт),
`app.js` (163 209 байт), все с HTTP 200. Хеши и размеры сверены,
оба JS-файла прошли `node --check`. Это проверка сохранности и синтаксиса,
не функциональный аудит сайта.

## Известные ошибки и ограничения

| Симптом | Действие |
|---|---|
| `curl` возвращает 401 | Использовать авторизованный Chrome. Это не означает, что сайт недоступен пользователю. |
| Нет `DevToolsActivePort` или соединение отклонено | Проверить работающий Chrome и включение удалённой отладки. Файл сам по себе не гарантирует живое соединение. |
| HTTP-подключение к `127.0.0.1:9222` даёт 404 на `/json/version/` | Использовать WebSocket из `DevToolsActivePort`; именно так подключение было проверено. |
| Таймаут соединения | Проверить диалог `Allow remote debugging?`. После завершения неудачной попытки повторить подключение. |
| Скрипт не находит контекст | Открыть прототип в нужном профиле Chrome. |
| Каталог уже существует | Выбрать новый каталог; старый снимок не удалять ради повтора. |
| Нет манифеста после ошибки | Снимок неполный. Не сообщать об успешной выгрузке; сохранить диагностику и повторить в новом каталоге. |
| Системный скриншот GNOME запрещён | Использовать `page.screenshot()` через CDP; не обходить системный запрет. |

## Озвучивание не включать

**Пользователь явно потребовал выключить озвучивание экрана.** Не включайте
`org.a11y.Status.ScreenReaderEnabled` или `IsEnabled` ради доступа к Chrome.
Их включение в первой попытке вызвало озвучивание; оба возвращены в `false`.
CDP не требует изменения этих настроек.

[`read_prototype_chrome.py`](tools/read_prototype_chrome.py) — вспомогательный
старый способ чтения через AT-SPI, а не основной способ просмотра. В текущей
сессии он читал текст и HTML из открытых DevTools даже после выключения флагов,
но это не гарантировано после перезапуска Chrome. Скрипт больше не включает
доступность автоматически. Если дерево пустое, переходите к CDP; не включайте
озвучивание. AT-SPI и эмуляция клавиатуры на Wayland оказались ненадёжны для
получения скриншотов и полного кода.
